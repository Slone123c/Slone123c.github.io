# Trace

Trace 是一套为「讲清楚底层原理」而生的界面语言：软件工程师的个人主页与技术文章——数据结构剖析（Go map）、算法（Raft）、大型系统（MySQL、Redis、Kubernetes、Docker）、方法论、数学。它的气质是 **一本被认真使用的工程笔记本**：纸色底、点阵网格、等宽编号，加上一抹信号橙和荧光笔绿带来的年轻与活力。

三条原则贯穿所有决定：

1. **看得见**——每个抽象都要落到一张图、一排格子或一步可执行的演示上。
2. **对得上**——正文、代码行、图示用同一个编号（Marker）互相指认，读者永远知道「这句话在说哪一行」。
3. **算得准**——数字、复杂度、源码行号、版本号都写出来；不确定的东西标为 Pitfall 或 Note，而不是含糊带过。

## 内容基本法

**语气**：像一个讲得清楚的同事在白板前讲解。用「你」，不用「您」；用「我们来看」，不用「本文将介绍」。先给直觉，再给定义，最后给证据（源码 / 公式 / 数据）。

- 标题写成问题或结论：「Raft 选主：为什么随机超时就够了」，不写「Raft 算法介绍」。
- 摘要说清「读完你会明白什么」，一句话，≤ 40 字。
- 术语第一次出现时给英文原名：负载因子（load factor）。之后统一用一种。
- 中英文、中文与数字之间加一个空格：「Go 1.24 起默认使用 Swiss Table」。
- 数字一律阿拉伯数字，带单位：`8` 个槽位、`150 ms`、`6.5`。
- 代码标识符一律用行内代码：`hmap.B`、`commitIndex`。
- 不用 emoji，不用感叹号，不用「非常」「超级」等强化词。活力来自颜色与版式，不来自语气。
- 栏目 kicker 用英文大写：`DATA STRUCTURE`、`DISTRIBUTED`、`SYSTEMS`、`METHOD`、`MATH`。

**讲解的骨架**（一篇原理文章的推荐章节顺序，每章前带两位编号 `01`、`02`……）：

| 章节 | 回答的问题 | 常用组件 |
| --- | --- | --- |
| 01 问题 | 它要解决什么？不用它会怎样？ | Callout `insight` |
| 02 结构 | 它长什么样？ | SpecSheet、Figure + Cells、Diagram |
| 03 过程 | 一次操作经过哪几步？ | Stepper、CodeBlock + Marker |
| 04 正确性 | 什么性质始终成立？为什么？ | Callout `invariant`、MathBlock |
| 05 代价 | 最坏情况、权衡、退化 | SpecSheet `amber`、Callout `pitfall` |
| 06 演进 | 新版本 / 替代方案改了什么 | Callout `note`、Compare |

方法论与数学文章同样适用：「过程」换成推导步骤，「正确性」换成证明。

## 视觉基础

**颜色**。底色只有 `bg`（纸色 / 终端黑）一种；`surface` 是抬起的卡片，`surface-sunken` 是凹下的代码与图示底板。正文 `ink`，次要 `ink-muted`，元信息 `ink-subtle`。

- `signal`（信号橙）是品牌色，也是「正在发生」的颜色：主按钮、当前步骤、正在被操作的格子。作为填充时上面的字一律 `on-signal`（深色），作为文字时用 `signal-text`。每屏的大面积 signal 不超过一处。
- `mark`（荧光笔绿）只表示「命中 / 结论」：查找命中的格子、正文 `<mark>` 下划线、代码高亮行左线。它是填充色，不做文字色。
- `cobalt` 表示「引用」：链接、指针、定义。`green` 表示「始终成立 / 最优」，`amber` 表示「陷阱 / 退化」。这两者永远和字形（∀ / !）或文字标签一起出现，不靠颜色单独区分。
- 每个强调色都有 `*-soft` 浅底，用于提示框和标签背景，上面的文字用对应强调色或 `ink`。
- 不用渐变、不用彩色阴影、不用半透明叠色。

**字体**。四个家族，各司其职：

- `display` · Bricolage Grotesque——标题，带一点不规整的个性，负责年轻感。
- `sans` · Instrument Sans——正文。中文全部回落到苹方 / 思源黑体。正文 `body` 17/30，行宽 ≤ 680px（约 38 个汉字）。
- `mono` · JetBrains Mono——代码、编号、kicker、规格数值。凡是「可以被精确核对的东西」都用等宽。
- `math` · STIX Two Text 斜体——公式与正文中的变量（`.tr-var`）。

页面标题用 `display`，一页一次；章节用 `h2` 并带 `kicker` 风格的两位章节号；导语用 `lead`。

**间距与版面**。4px 基准，`space-1`…`space-8`。文章页：正文 680px + 右侧目录 220px，两者间距 `space-8`。章节（h2）前 `space-7`，代码块与图示上下 `space-5`。主页卡片网格间距 `space-6`，三列，最小宽 300px。

**圆角**。`radius-xs` 行内代码与格子，`radius-sm` 按钮与提示框，`radius-md` 卡片、代码块与图示，`radius-full` 标签与编号圆点。不使用大于 12px 的圆角。

**描边、阴影与层次**。层次靠 1.5px 描边（`line`）表达，不靠阴影。唯一的投影是 `shadow-pop`：可点击卡片 hover 时上移 2px，落下 4px 硬边 ink 影（深色主题为 signal 影）——像便签被按起来。浮层用 `shadow-float`。

**点阵**。`grid-dot` 以 16px 间距铺在 Figure 与 Stepper 的舞台上，是「工程笔记本」的标志。只铺在图示区，不铺满整页。

**状态**。Hover：边框变 `ink` 或背景变 `surface-sunken`。键盘焦点：`focus-ring`，2px 底色间隙 + 2px 实心钴蓝环，在所有面上 ≥ 3:1。Disabled：45% 不透明度。

**动效**。只用于解释：Stepper 切换时格子 0.2s 过渡，`active` 格子上浮 3px。不做入场动画、视差、自动轮播。

## 图示规范

所有示意图放在 `Figure` 里，用同一套视觉词汇，跨领域复用：

| 概念 | 画法 | token |
| --- | --- | --- |
| 内存 / 数组 / 日志 / 桶 | `Cells` 一排格子，下方等宽索引 | `surface` + `line-strong` |
| 正在被操作的那一个 | 格子填充、上浮 3px | `signal` / `on-signal` |
| 查找命中 / 结论 | 格子填充 | `mark` / `on-mark` |
| 指针 / 引用 / 投票 | 浅底或 1.5px 直角折线箭头 | `cobalt` / `cobalt-soft` |
| 已删除 / 已迁移 | 删除线 + 凹面底 | `surface-sunken` / `ink-subtle` |
| 节点（Raft、K8s Pod、MySQL 实例） | `radius-sm` 方块，等宽名字 | `surface` + `line-strong` |
| 标注 | 编号圆点 Marker，与正文和代码行对应 | `signal` |
| 组件拓扑 / 请求链路 | `Diagram`：网格节点 + 直角折线箭头 + 分组边界；配 `Stepper` + `highlight` 逐步点亮 | `ink` / `signal` / `cobalt` |
| 方案取舍 | `Compare`：编号列 + `+ − ·` 判定字形 | `green` / `amber` |

规则：线宽 1.5px；连线用直角折线；箭头实心三角；图中文字等宽 12–13px；一张图里强调色 ≤ 2 种。

## 国际主义网格

Trace 的「工程严谨」那一半借自国际主义风格（Swiss Style），用在需要客观呈现结构与取舍的地方：系统剖析页、`Compare`、`Diagram`。

- **网格先于内容**。系统剖析页用 12 列网格、`space-5` 列间距：左 3 列放章节编号和标题，右 9 列放正文与图。`Diagram` 的节点坐标以格为单位，天然对齐网格。
- **齐左，不居中**。标题、表格、图注都齐左、右边自然参差。整个系统里只有公式（MathBlock）居中。
- **两种线，各有职责**。3px `ink` 结构线标出一个区块的开始（页眉信息栏、章节头、对比表顶、图示顶、分组边界）；1px `line` 分隔线只分隔同一区块内的行。不画外框，不用斑马纹。
- **数字也是版面元素**。章节编号 `01` 用 `display` 字体做大字（44px）；系统剖析页的系列号可以放大到 220px，用 `signal` 着色，作为全页唯一的大色块。
- **信息栏**。页面顶部是一行四列的等宽信息栏（Series / Subject / Published / Reading），标签全部大写，并放在 3px 结构线下。
- **信号橙只出现一处**。在 Swiss 版式里，signal 只用于大号系列号、`focus` 列顶部的粗条、`active` 路径三者之一或两者，其余全部是黑、白、灰。
- 文章页（ArticlePage）保留笔记本气质，系统剖析页（SystemPage）走网格气质，两者共享同一套 token 和组件。

**两种版式怎么选**。`Compare` 和 `Diagram` 都有 `variant`：

| | `notebook`（默认） | `swiss` |
| --- | --- | --- |
| 用在 | 文章页、单步演示 | 系统剖析页、选型总览 |
| 层次靠 | 卡片 + 软底色 + 硬边影 | 粗细两种线 + 留白 |
| 编号 | Marker 圆点贴纸 | 大号两位数字 |
| 焦点 | 荧光绿铺底 + 橙色贴纸 / 硬影节点 | 信号橙粗条 / 橙色节点 |
| 结论 | 有「→ 结论」条 | 不下结论，交给正文 |

同一页只用一种版式。

## 个人介绍页

`ProfilePage` 同时服务两种读者：30 秒扫一眼的招聘方，和花 5 分钟核实深度的面试官。所以按倒金字塔排列，越往上越概括，越往下证据越多。

- **01 第一屏**：状态胶囊、名字、一句话定位、一句价值陈述，主按钮「下载简历」，右侧用 `SpecSheet` 做个人规格表。不滚动就能完成判断。
- **02 能力地图**：按「深入 / 熟练 / 了解」分三列，每项都链接到项目或文章。没有证据的项目写「学习中」，不写百分比。
- **03 精选项目**：主项目写「问题 → 方案 → 结果」，配 `SpecSheet` 数字和笔记本版 `Diagram`；次要项目两张小卡。写清角色和规模，内部系统名称要抽象化，数字只写量级。
- **04 经历 / 05 技术写作 / 06 我怎么工作 / 07 联系**：章节头沿用 Swiss 网格（左 3 列大号编号），内容组件用笔记本版。
- 顶部「30 秒速览 / 完整版」切换：速览只显示 01–04 与 07。打印样式直接输出 A4 简历，网页和 PDF 共用一份内容。
- 信号橙只用在主按钮和状态胶囊上，把视线引向「下载简历」和「在看机会」。

## 图标

Trace 不附带图标库，刻意用**字形**代替图标：`→ ←`（方向）、`≡`（定义）、`∀`（不变量）、`!`（陷阱）、`i`（注）、`∅`（空槽）、`#`（标签前缀）、`No.017`（编号）。它们来自等宽字体，天然与代码和数字对齐。

如确需图标（导航、社交链接），使用 1.5px 描边、24px 网格的线性图标，颜色继承 `ink` / `ink-muted`，并在此处补一个资源组记录来源。当前没有提供 logo：站点名用 `display` 字体直接排出，前面加一个 10px 的 `signal` 小方块作为记号。

## 组件速查

`window.Trace` 提供：`Button`、`Tag`、`Marker`、`ArticleCard`、`Outline`、`Callout`、`SpecSheet`、`MathBlock`、`CodeBlock`、`Cells`、`Stepper`、`Figure`、`Compare`、`Diagram`。页面示例见 `ArticlePage`（文章页）、`HomePage`（主页）、`SystemPage`（系统剖析页，国际主义网格版式）与 `ProfilePage`（个人介绍 / 求职页）。正文容器加 `.tr-prose` 即获得行内代码、`<mark>` 与链接的样式。
